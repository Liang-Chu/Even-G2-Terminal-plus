# Architecture

The Windows tray launches the native monitoring backend (`NativeHost`). Phone/G2 connect over authenticated HTTP/SSE. A small extension in each normal Pi TUI exchanges bounded snapshots and expiring commands through `.local/native`. Each session's completion independently feeds the existing journal and Glance FCM worker.

The browser/Hub connection pool keeps an independent authenticated SSE client per saved computer. Lists and monitoring summaries merge globally; a UI session key scopes the original key by the computer URL, so identical saved keys on different computers cannot collide. Every command/history request resolves that scope back to exactly one host and strips it before sending. Server keys are stored only on the viewing device, never shared between backends. Source identity comes from authenticated `/api/host`: a persistent installation ID and the local Tailscale DNS device label, with an explicit hostname fallback. A partial outage preserves the affected host's cached Watch rows, reports unknown activity and does not block the other hosts or trigger a completion. G2 presence leases are released on the old host when switching sources.

Codex and Claude connectors use the same snapshot/command contract. Codex's wrapper owns an authenticated loopback App Server and observes native TUI traffic; Claude uses per-launch hooks and an MCP channel. Separate read-only observers cover ordinary Codex local rollouts and Claude's official hooks. They never create a second writer or grant remote control. Claude preparation records owned global hook handlers; a bounded private event queue binds lifecycle records to the native process/start identity. Known background work and custom Stop hooks prevent premature completion. See [connector setup and limits](connectors.md). Closing the monitor never closes these native wrappers.

Selecting a connected session reuses its actual Pi terminal. Selecting a closed session opens its original file in a visible terminal. The monitor never kills native Pi on unwatch or shutdown. An unregistered Pi process can block resuming an existing session until `/reload` connects it, avoiding accidental concurrent writers during migration. It does not block creating a separate fresh session.

The extension accepts TUI mode only. Structured Pi events feed the existing normalizer/store; no terminal scraping or model prompt changes. Changed snapshots publish at most four times per second; unchanged heartbeat every two seconds. Visible text is bounded to 80 entries / 60,000 characters and 20,000 characters of current reply. Thinking/raw tool payloads are excluded.

`NativeHost` checks snapshots every 300 ms and marks missing heartbeat offline after six seconds. Offline is not completion and does not revoke membership. A window switching sessions disconnects the previous session immediately. Dead background stores are released; watch metadata persists. Extension reloads keep session stores stable and establish a completion baseline, so old completions do not replay after monitoring restarts.

Commands target an extension instance and session key with a unique ID and five-second deadline. The extension removes the command before invoking Pi, checks the current session/idle state, then acknowledges. Six seconds without acknowledgement means uncertain delivery, never automatic resubmission. Launch reservations prevent duplicate selection during startup. An alive process with a stale heartbeat does not authorize another launch.

Each monitored `agent_settled` independently reaches `NotificationJournal`, including while other sessions run. Tool completions, idle snapshots, closed windows and network loss do not become job completion. The host does not guarantee completion delivery while stopped; it resumes with current state and no historical replay. Existing durable subscriptions, FID sends and bounded retries remain in [Glance push](glance-push.md).

The native Windows Forms tray opens the existing browser manager automatically; a second launch signals the current tray. Before each explicit opening it posts a new UUID to `/api/desktop/open`. NativeHost applies a rolling 24-hour watch selection and persists the latest request ID, so request retries cannot undo manual unwatch. Browser refresh/reconnect and backend startup do not apply this policy. Setting watch membership never launches closed terminals or stops running ones; selecting a closed session opens its original terminal. Desktop rendering puts session management first, with direct Watch checkboxes and Watched / All sessions filters, followed by prompt relay. Lists sort by actual activity/file modification time; heartbeat/selection do not bump idle sessions. The backend is detached with no stdio pipes owned by the tray. Quit exits only the tray. Phone/G2 retain a bounded conversation view.

The offline setup EXE embeds the official Node runtime, its license and a clean locked production dependency tree. It extracts into immutable `versions/<version>-<payload hash>` directories and keeps `.local` at the installation base. The tray prefers bundled Node; a source checkout can still use PATH. The installer stops only the matching tray and authenticated native-monitor backend, and never kills Node/CLI process trees. Upgrades retain older payloads used by native terminals; uninstall refuses active terminals and preserves `.local`. The portable ZIP has the same runtime but no installed marker, so it keeps data beside its EXE.

Linux shares the same backend, browser and connector protocol. Its offline `.run` installer verifies the embedded archive and every payload hash, installs per-user version directories, and retains XDG data across upgrades/uninstall. A systemd user service uses `KillMode=process`; disabling autostart retains the unit definition so its lifetime policy does not revert while native terminals are alive. Without a user systemd manager, the launcher starts a detached backend and supports XDG graphical-login autostart. It never enables system-wide lingering or changes firewall rules automatically.

Graphical Linux launches an available native terminal emulator with literal argv. Headless Linux creates named `pilot-*` sessions in the user's tmux server, passing connector paths per session because a preexisting tmux server can have an old environment. Watch does not create terminal windows. `/proc` discovery prevents opening a second writer for an unregistered CLI. Terminal attach/detach and monitor lifetime remain independent.

Claude on Linux owns a Python-standard-library PTY for its launched CLI. A private Unix socket accepts only same-user requests, checks a random capability, process start identity, snapshot freshness, session/instance/run and deadline, then writes one Escape to that PTY. It rejects repeated Stop for the same run. No process-wide signal or shared-terminal keystroke is used. Completion still requires the existing native transcript/event confirmation; byte delivery is not completion.

The [v1 QR](glance-qr-v1.md) puts the current connection key in a URL fragment. Glance derives `/api/glance` from the same origin; Even Hub uses manual URL/key entry. Fresh installs generate distinct persistent keys and omit Firebase credentials. The shared key grants control; the notification-only credential remains scoped. `/api/pairing` requires control authorization and disables caching. Paired API clients authenticate with a bearer key; authenticated responses reflect the caller origin, and preflight allows only the declared bearer/JSON/event headers. No credentialed-cookie CORS is enabled. Static content retains origin restrictions.


Phone slash commands route to explicit native operations: Pi compaction/model selection and Codex thread compaction. Unsupported slash commands fail before model-prompt delivery. A shared bounded `InteractionBroker` holds ephemeral, instance-scoped questions, options and callbacks. The authenticated response endpoint delivers a request-ID-bound answer through the existing mailbox even while the agent waits. Requests are claimed before sending, never automatically retried, and removed on expiry/session changes/connector shutdown. Ordinary model text is not parsed into commands or approval controls. Codex's terminal link arbitrates local and remote replies; Claude's official Channel permission relay validates the original request ID. Phone and G2 render the same structured questions, with long/sensitive forms handed to the phone.

G2 uses a native single-column conversation list and native full-text readers, with small cached header/footer images. Startup shows a connection notice and an input-only list automatically hydrates when the first history arrives. The phone receives backend SSE updates and batches visible conversation changes at most once every two seconds while the input row is selected. Native navigation, expanded reading, recording and menus retain their mounted snapshot; returning shows current messages. Identical labels cause no rebuild. Clock/status updates use cached image tiles or basic-view native text without rebuilding the list. SDK operations remain serialized, with each two-tile bar sent consecutively and other queued operations allowed between bars; backend reconnection and menu dismissal retain acknowledged content, while BLE recovery restores it.

References: [Pi extension API](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md), Even SDK 0.0.16 and the [Glance contract](glance-push.md). See [release status](release-status.md) for validation and limits.

Duplicate native windows for one session are resolved by actual conversation activity, never by heartbeat recency. The chosen owner stays stable until another window receives newer activity. A stale heartbeat is offline, not idle, and never invents a completion.

The phone Hub starts on a device-grouped session browser. Device identity uses the saved URL/id, not the display name. Groups preserve offline Watch entries and sort by recent updates. Collapsed device groups render no rows; expanded groups initially render eight, with explicit loading of more rows. Conversation DOM is updated only when its phone page is visible; G2 rendering and monitoring remain independent.
