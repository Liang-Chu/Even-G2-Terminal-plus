# Hub voice input

## Setup

1. Upload the current `.ehpk` listed in the README and use the current native desktop backend.
2. In the phone's Terminal+ page, tap **Voice** beside **Connection**.
3. Select **OpenAI** or **ElevenLabs Scribe** (`scribe_v2`), paste that service's API key, choose auto/Chinese/English, and Save. OpenAI defaults to **GPT Transcribe** (`gpt-transcribe`) for streamed text in new or model-less configurations. Existing explicit Whisper choices, provider and API keys are retained. GPT Transcribe uses the same OpenAI key as Whisper; the account must allow the chosen model.

   OpenAI has scheduled `whisper-1` removal for February 26, 2027. Before that date, switch any explicitly saved Whisper choice to **GPT Transcribe** in Voice settings. Version **1.1.12** changes the default; earlier **1.1.11** also supports this manual switch. [Official deprecation schedule](https://developers.openai.com/api/docs/deprecations)
4. Allow G2 microphone access when Even Hub requests it. Open a watched session with a connected terminal.
5. In an input-capable session, select **New prompt** to enter an empty editor. Tap again to start recording, and tap to stop. The cursor pulses only while recording. Each recording adds one segment, even while an earlier segment transcribes. Hold deletes the latest segment immediately, then once per second until release; deleting everything keeps editing open. **An empty draft returns directly on double tap.** Whitespace-only text and deleting all segments also count as empty. Recorded audio or pending transcription still requires confirmation, even before text appears. **Otherwise double tap opens a native confirmation list: Send & exit (selected by default), or Exit only.** Opening it stops recording and retains the draft; nothing is sent until a choice is tapped. Send & exit returns to the conversation and sends the completed draft once; an empty draft just returns. Pending transcription finishes before the confirmed send. Exit only discards the draft and cancels pending transcription. Double tap or Back on the confirmation returns to editing without discarding anything. The phone shows finishing/sending status. Transcription failures return to editing without sending a partial draft; uncertain delivery is never retried. The editor menu starts with **Back**, which discards the draft and returns without sending; **Send** remains available for a completed draft. Opening the menu stops recording and retains the draft. Swipes read longer drafts. The phone also offers editable review and Send/Cancel.

OpenAI and ElevenLabs keys are separate from the desktop/Glance connection key. Entering or saving a key makes no API request. Switching providers never copies the other provider's key. No key is baked into the package or included in the pairing QR. Save persists keys and voice settings by default within the same app identity. Terminal+ 1.1.15 keeps Hub ID `local.terminalplus.app`; keys and connections from `local.evenpilot.app` may not transfer, so re-enter each computer's URL/key and your transcription key if needed. Keys use Even SDK app storage, or localStorage in browser preview; this is not a secure keychain. Clear all keys removes the stored and in-memory keys while preserving model/language preferences. A storage failure is shown and leaves the dialog open so saving or clearing can be retried.

GPT Transcribe and Whisper use an OpenAI API Platform key, with access to the audio transcription endpoint and available API quota. An existing OpenAI key used for GPT API calls can also be used if those permissions are enabled; no separate transcription key is required. ChatGPT subscription sign-in is not an API key. This app calls the official OpenAI endpoint directly, so a third-party reseller's key cannot be substituted.

## Data flow and limits

G2 mic → Even app / Hub WebView → selected speech service over HTTPS → review on G2/phone → confirmed text to the selected CLI session on Windows or Linux.

The desktop never receives audio or speech API credentials. PCM and WAV are temporary memory buffers, not saved audio files. Each recording is capped at 60 seconds; each cloud request times out after 45 seconds. A draft allows up to four pending transcriptions, 64 segments and 32,000 characters. Transcriptions stay in recording order even if a later request finishes first. Delete aborts the removed segment's request. There is no background or always-on recording. Switching sessions, changing the bridge, connection loss, exiting or cancelling invalidates the draft and aborts pending transcription. A prompt includes the originally selected session key; the backend rejects it if selection changed. An uncertain prompt delivery is not automatically retried.

HTTP requests are multipart POST to the following fixed endpoints, with credentials in headers only. No arbitrary endpoint or HTTP redirect is allowed.

| Provider | Endpoint | Authentication | Model |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1/audio/transcriptions` | `Authorization: Bearer …` | `gpt-transcribe` (default) or explicitly selected `whisper-1` |
| ElevenLabs | `https://api.elevenlabs.io/v1/speech-to-text` | `xi-api-key: …` | `scribe_v2` |

The SDK delivers PCM signed 16-bit little-endian, 16 kHz, mono. The client wraps it in WAV metadata before uploading. The manifest retains the working dynamic bridge network permission and declares `g2-microphone`. Provider origins are fixed in code; each desktop's LAN/Tailscale address remains runtime configuration.

The phone needs internet access to the selected provider independently of its Tailscale link to the PC. API usage is billed by the selected provider. Audio retention at that provider follows the account/service policy; this app does not request or promise zero retention.

## Returning to the conversation

One sentence means one recording segment, not punctuation detected by the speech service. Hold deletes the current recording or latest segment, including its pending transcription. The initial deletion happens on LONG_PRESS, repeats every 1,000 ms, and stops on LONG_PRESS_RELEASE, menu opening, finishing, disconnect or session change. This rate is a product trial value, not an industry standard. Double tap returns directly for an empty draft; otherwise it opens confirmation. Send & exit commits the draft and returns; Exit only or the phone's Cancel discards it and revokes pending transcription. Finishing transcription while the confirmation is visible never sends automatically or resets its selection. While the editor is still being replaced, a duplicate double cannot exit the app. Once the conversation is displayed, double tap requests the official exit confirmation (`shutDownPageContainer(1)`), regardless of agent count or connectivity. Cancelling keeps the session open; exiting leaves the native terminal running. To interrupt a task, choose **Terminate task**, the first app action before **Sessions** in the conversation menu. System menu rows are inserted by firmware and their positions are not configurable through the SDK. It requests interruption of the current instruction; it does not suspend the CLI process. Pi/Codex use runtime APIs and Claude forwards one Escape to its bound native console or Linux PTY; see [connector limits](connectors.md). Exit is also available in the system contextual menu. A finish is bound to its captured session; session/connection changes cancel it. Removed or cancelled recordings cannot send late text.

Even SDK 0.0.16 exposes CLICK, DOUBLE_CLICK, LONG_PRESS and LONG_PRESS_RELEASE. This release uses those events directly, with no combination window or inferred triple tap. A 100 ms guard ignores duplicate envelopes without delaying the initial action. Tests verify event dispatch and page transitions; firmware timing and physical usability still require a G2 check.

## Transcription latency

Tap and double-tap gestures dispatch immediately. Existing Whisper and ElevenLabs paths still upload a completed recording and wait for final text. With **GPT Transcribe**, the same HTTPS request uses `stream=true`: partial text appears while the file is processed. The confirmation's Send & exit can commit a pending draft, but prompt delivery waits for every final event; the phone/menu Send action still requires a completed draft. The app waits for microphone shutdown acknowledgement before uploading. Streams interrupted before completion fail instead of promoting partial text to a final draft; removed segments abort the stream. No automatic paid retries or silent model fallback occur.

This improves time to visible text, not a guaranteed end-to-end latency. Upload and provider time depend on the phone network, recording and account. True transcription while speaking requires a separate realtime audio connection, which this release does not implement. The multipart request uses `languages[]` for `gpt-transcribe` and `language` for Whisper. See the [official file transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text) and [live transcription guide](https://developers.openai.com/api/docs/guides/realtime-transcription), checked 2026-10-07. Automated streaming tests use synthetic responses; no real paid request or phone latency benchmark is claimed.
